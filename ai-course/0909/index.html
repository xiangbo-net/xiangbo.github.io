案例1：国内获客

适用：增长班 V2.6 ｜ 模块一 获客赋能 ｜ 案例1 国内网上获客
教学基准日：2026-09-07 ｜ 全部数据为教学模拟；步骤 2—3 涉及真实公开信息，仅限课堂演示使用
所有路径以案例根目录（03_模块一_获客赋能/案例1_国内获客/）为基准。

使用说明

1.
本手册将整条获客链路拆成 7 个步骤；每步给出可直接复制的提示词（置于代码块内）。
2.
按顺序逐段复制执行；每步完成后人工检查（见各步"人工检查"），再进入下一步。
3.
步骤 2 需要调用「地图获客专家」（课堂中称"国内精准获客专家"），必须课前完成安装并配置高德 API Key（详见 07_学员任务书.md 前置要求）。
4.
步骤 2—5 产物实时生成到 03_output/；步骤 6 写入 04_archive/线索库.xlsx；步骤 7 生成 06_webapp/index.html。
5.
任何一步失败，参照 08_讲师演示指引.md 失败预案降级执行。

步骤 1｜阅读企业介绍，生成理想客户画像与搜索规则

业务目标：只阅读 01_input/01_企业基础资料/ 下的企业 A 资料，输出"理想客户画像与搜索规则"，作为后续真实搜索的输入条件。

plain text
你是企业业务分析师。请只使用本案例目录内 01_input/01_企业基础资料/ 下的四份文件：
企业A_公司介绍.md、企业A_产品与服务.md、企业A_案例与资质.md、企业A_FAQ与禁用表达.md。

任务：基于企业A（华东智节工业设备有限公司，工业节能设备与空压系统企业）的资料，
生成"理想客户画像与搜索规则"，并在分析中区分：已核验事实、教学模拟证据、AI分析、
置信度、待确认事项、建议动作。禁止臆测，缺失信息写"未找到/待确认"。

输出要求：将结果保存到 03_output/理想客户画像与搜索规则_<当前日期>.md（日期格式YYYY-MM-DD）。
文件必须包含：
1. 处理摘要（结论先行）
2. 理想客户画像卡（行业/区域/规模/用气特征/场景/采购角色）
3. 需求信号与优先级（高/中/低）
4. 排除条件
5. 搜索规则：行业关键词、城市清单、搜索排除词、逐条记录需回填的字段（含来源与日期）
6. 线索质量评分维度初稿（供步骤4细化）
7. 置信度与待确认事项
8. 人工检查与教学边界（注明：画像为AI分析产物，不含真实企业对外触达授权）

人工检查：本步骤不得擅自确认线索等级、负责人、报价、折扣、交期、合同、
客户联系或公开发布；画像中的排除条件与评分阈值需标为"待销售负责人复核"。

通过标准：输出可追溯到 01_input/01_企业基础资料/ 内文件；路径有效；
内容足以作为步骤2调用地图获客专家时的输入条件。

人工检查：画像行业/规模是否覆盖企业 A 实际业务；排除条件是否过严或过松。

步骤 2｜调用「地图获客专家」，按画像搜索 20 条真实候选客户

业务目标：将步骤 1 画像输入地图获客专家（基于高德 POI 的国内精准获客工具），在华东重点城市按行业关键词真实检索，产出 20 条候选企业清单。

plain text
【前置】本步骤需在已安装并配置高德API Key的「地图获客专家」会话中执行。
若尚未安装或未配置Key，先完成安装与配置（见学员任务书/讲师指引前置要求），再继续。

请在「地图获客专家」会话中发起：
我已生成企业的理想客户画像与搜索规则，文件在
03_output/理想客户画像与搜索规则_<当前日期>.md，
请先阅读该文件，再按其中第"搜索规则"部分执行：

1. 按行业关键词 × 重点城市（苏州、无锡、宁波、上海、常州优先）检索企业POI，
   关键词单次不超过3个，每城市×关键词最多2页，控制调用量；
2. 应用搜索排除词过滤错配主体（维修/回收/贸易/咨询/餐饮/零售等）；
3. 尽量凑齐20条有效候选，不足时扩展到次选城市（嘉兴、南通、湖州、杭州、绍兴）；
4. 每条候选必须回填：企业名称、城市/区县/地址、行业与主营、官网或公开电话、
   统一社会信用代码（如可得）、需求信号（环评/招聘/新厂/官网动态）与公开日期、
   来源渠道与检索日期；
5. 只采集企业公开信息，不采集个人手机/个人微信等个人敏感信息；
6. 结果整理保存为 03_output/候选客户名单_<当前日期>.md，并同时给出一个
   便于后续逐条核验的清单（含来源列）。

人工检查：名单仅作课堂演示用途，不得对名单中真实企业发起任何电话/邮件触达。
如命中明显错配主体，保留并标注原因，不臆测、不删除异常项。

人工检查：候选是否 ≥20 条且每条有来源；若专家 Key 配额不足或检索异常，按失败预案降级。

步骤 3｜候选企业主体核验、资料补全与去重

业务目标：对步骤 2 的 20 条候选，逐条到公网与官网搜索补全、校验主体信息并去重，剔除错配主体。

plain text
你是企业信息核验分析师。读取 03_output/候选客户名单_<当前日期>.md，
对其中每条候选企业执行核验：

1. 主体核验：通过公网搜索/企业官网/公开查询渠道核对企业真实名称、
   是否真实存在、行业与主营是否与画像匹配；记录核验来源与日期。
2. 信息补全：补全官网地址、办公地址、公开联系电话、规模信息（人数/注册资本，
   如可得）等公开字段；补不全的写"未找到/待确认"。
3. 去重与错配剔除：对重复主体只保留一条并提示；对明显错配（贸易商/服务商/
   非目标行业/华东以外）标记"建议剔除"，保留证据行。
4. 每条记录维护：主体核验状态（已核验/待核验/剔除建议）、证据链接或来源、
   核验日期、待确认事项。
5. 输出：保存为 03_output/候选核验与去重结果_<当前日期>.md，
   结构包含：处理摘要/核验事实/证据/分析/待确认/人工检查/下一步输入。

人工检查：剔除与合并动作必须经人确认，AI仅给出建议与证据；
涉及企业真实信息仅限课堂使用，不得外发。

人工检查：讲师或学员确认去重/剔除建议是否合理；保留的候选应≥10 条。

步骤 4｜建立线索质量评价标准，多维评分并分三级

业务目标：在步骤 1 初稿基础上建立正式评分标准，对核验后的候选从多维度评分，分为 A / B / C 三档。

plain text
你是销售线索分析师。读取 03_output/候选核验与去重结果_<当前日期>.md，
并参考 03_output/理想客户画像与搜索规则_<当前日期>.md 中"评分维度初稿"：

1. 建立线索质量评价标准：明确评分维度、权重与打分细则。建议维度：
   行业命中(25%)、区域命中(15%)、规模命中(15%)、需求信号(30%)、信息完整度(15%)；
   可结合核验结果细化每维度1—5分评分锚点。
2. 对每条候选逐维度打分并计算加权总分，给出分级：
   A级(最优,建议阈值≥80)、B级(70—79)、C级(<70)。
3. 输出分级结果表（企业/城市/总分/等级/关键命中点/关键缺失点/下一步建议），
   保存为 03_output/线索评分表_<当前日期>.md，
   另将评分标准单独保存为 03_output/线索评分标准_<当前日期>.md。

人工检查：等级划分、阈值设定必须由人确认；AI不得擅自定义某条为"A级
并据此对外触达"。C级不代表删除，标注补充证据方向即可。

人工检查：评分结果应呈"少量 A、较多 B、部分 C"的分布感（A 级建议 3—5 条内），由人工复核打分合理性。

步骤 5｜对最优等级目标客户撰写初次开发话术

业务目标：仅针对 A 级目标客户撰写初次开发建议话术；根据已获得的有效联系方式确定形式（电话话术或邮件正文）。

plain text
你是销售开发文案顾问。读取 03_output/线索评分表_<当前日期>.md，
只对其中 A 级（最优等级）目标客户撰写初次开发话术：

1. 逐家判断可用联系方式类型：有企业公开电话/官网联系电话→写电话话术(≤60秒)；
   有官网公开邮箱或在线表单→写邮件正文；两者都有→都写并标注首选。
2. 话术必须可验证地引用该企业公开信息（如：新增产线、新建厂区、所属行业、
   所在园区等），体现"我了解你"，但不得编造未核验信息。
3. 严格遵守合规：不承诺"绝对节能/行业第一/零风险/保证回本/永久免维护"等禁用表达；
   不虚构案例效果数字；报价与折扣一律留白待人工。
4. 每条话术附：触发场景、开场钩子、价值点（对应企业A产品与服务）、
   下一步建议动作（如"邀约15分钟能耗诊断沟通"）、待人工确认项。
5. 输出：保存为 03_output/初次开发话术_<当前日期>.md。

人工检查：任何话术在发送/拨打前必须经企业A销售负责人审核；
对真实企业仅作课堂演练，禁止实际外呼或发送。

人工检查：话术是否贴合该企业公开信号、是否含禁用表达/未核验承诺。

步骤 6｜将全部候选名单写入 archive 线索库

业务目标：将完整候选名单（含核验、评分与话术结论）回写到 04_archive/线索库.xlsx，形成可复用的线索台账。

plain text
你是线索库管理员。请把本案例当前所有候选线索整理并写入
04_archive/线索库.xlsx（沿用该文件既有工作表与表头，勿改动结构）：

1. 线索数据表：写入全部候选企业一行一条；字段含：线索ID(LEAD-CN-序号)、
   企业名称、国家/地区、行业、城市/区域、企业规模、获客路径(地图POI/官网/搜索)、
   来源与来源网址、主体核验信息与核验状态、评分结果(总分与等级)、需求信号与证据、
   联系人/职务/联系方式(仅公开信息，无则留"待确认")、AI判断与置信度、
   待确认事项、是否人工确认(初始"否")、首次开发形式(电话/邮件)、负责人、
   下一步行动、下一步日期、线索状态(待跟进)、创建时间、更新时间。
2. 同步更新：字段说明表、Sources_数据源表（记录本次检索渠道与日期）、
   Checks_检查表（标记写入状态通过/异常）。
3. 写入后报告：共写入多少条、各等级数量、待人工确认项清单。

人工检查：线索等级/负责人/报价/折扣/交期/合同/客户联系/公开发布
一律不得由AI确认，保持"待确认"并交人工；ID与日期格式按既有数据规则。

人工检查：打开 04_archive/线索库.xlsx 核对写入行数与等级分布、检查表状态。

你是前端开发者。请基于 03_output/ 下的画像、评分表与话术成果，
以及 04_archive/线索库.xlsx 的线索数据，生成一个"国内获客线索工作看板"

案例4：企业内容经营全流程

用途：本手册是案例4「企业内容经营全流程」课堂演示的分步操作提示词。每段提示词以代码块呈现，直接复制到 AI 助手（WorkBuddy 等）对话窗口执行即可。
工作目录：所有路径均相对于案例根目录 案例4_企业内容经营全流程/。
基准日期：2026-09-07｜案例ID：案例4

通用规则（每一步都默认生效）

1. 事实分层：所有产出须区分「已核验事实 / 教学模拟证据 / AI 分析 / 置信度 / 待确认事项 / 建议动作」，AI 推测不得写成事实。

2. 商业边界：不擅自定义线索等级、负责人、报价、折扣、交期、合同、客户联系或公开发布；涉及此类字段一律标注"待人工确认"。

3. 异常规则：缺失信息写"未找到/待确认"；遇到重复或冲突时保留证据并提示人工处理；禁止臆测。

4. 口径基准：企业事实以 01_input/01_企业基本资料/ 为准，其中《企业B_品牌与内容规范.md》为最高合规口径。

5. 教学红线：真实企业信息仅用于课堂演示，禁止对外触达；不采集个人隐私；API Key 保密，不写入任何案例文件。

第一步

业务目标：检查项目工作的基础准备——定位卡、选题库、台账；缺失则创建，已有则与用户共创修订。

plain text
你是企业内容经营顾问。请执行「案例4 · 第一步：基础准备检查」。工作目录为案例根目录。

【输入】
1. 检查 01_input/02_经营定位/ 下是否存在「自媒体经营内容定位卡.md」；
2. 检查 04_archive/ 下是否存在「内容选题库.csv」与「内容经营台账.csv」；
3. 生成定位卡时读取：01_input/01_企业基本资料/ 下全部文件（公司介绍、产品与服务介绍、解决方案与案例、品牌与内容规范、常见问题FAQ与内容口径）。

【任务】
A. 定位卡检查：若 01_input/02_经营定位/自媒体经营内容定位卡.md 不存在，依据 01_input/01_企业基本资料/ 全部资料生成一份，内容包含：
   1. 账号定位与一句话简介；2. 理想客户画像（角色、行业、典型痛点、决策关注点）；3. 内容支柱（四类创作类型：客户痛点 / 案例成果与客户收益 / 行业内幕与专业判断 / 产品与解决方案优势，各配 2-3 个方向说明）；4. 选题公式（目标客户＋具体场景＋真实问题＋专业判断/解决方法＋客户收益）；5. 渠道矩阵（主渠道长文 + 衍生渠道图文/短内容）；6. 发布节奏（默认每日一篇，长文为先，依据长文生成其他形式和平台内容）；7. 语气与表达边界（引用品牌与内容规范要点）。
   若定位卡已存在，读取并向用户汇报其要点，邀请用户共创修订（逐项确认或提出修改意见）。
B. 选题库检查：若 04_archive/内容选题库.csv 不存在，按上述统一字段创建空表（仅表头）。若已存在，读取并汇报选题数量、创作类型分布，邀请用户修订。
C. 台账检查：若 04_archive/内容经营台账.csv 不存在，按上述统一字段创建空表（仅表头）。若已存在，读取并汇报当月排期情况，邀请用户修订。

【输出】
- 新建的定位卡保存至 01_input/02_经营定位/自媒体经营内容定位卡.md；
- 新建的选题库/台账保存至 04_archive/ 对应文件；
- 检查与处理结果写入 03_output/步骤1_基础准备检查报告_YYYYMMDD.md（YYYYMMDD 为当日日期），结构：处理摘要、检查项清单（存在/新建/修订）、事实与证据（引用的源文件路径）、待确认事项、人工检查、下一步输入。

【人工检查事项】
- 定位卡中的客户画像是否可追溯到企业基本资料（不得臆测）；
- 四类创作类型与选题公式表述是否与本手册一致；
- 是否有价格、交期、效果承诺等未标注"待人工确认"的内容。

【异常规则】
- 文件缺失写"未找到"，不要虚构已有内容；
- 企业资料之间口径冲突时，保留双方证据并提示人工处理（以品牌与内容规范为准）；
- 禁止臆测。

【通过标准】
- 三项检查全部有明确结论（存在/新建/修订）；
- 生成或修订后的文件路径有效、字段符合数据文件规范；
- 检查报告可作为第二步输入。

第二步

业务目标：与用户确认创作类型与创作计划（数量、频度、选题、类型），并按月创建台账排期。

plain text
你是企业内容经营顾问。请执行「案例4 · 第二步：确定创作类型与计划」。工作目录为案例根目录。

【输入】
1. 01_input/02_经营定位/自媒体经营内容定位卡.md（第一步产出）；
2. 01_input/01_企业基本资料/ 全部文件（选题的事实与口径来源）；
3. 01_input/03_素材库/素材清单.md（可用素材索引）；
4. 04_archive/内容选题库.csv 与 04_archive/内容经营台账.csv（第一步产出）。

【任务】
A. 向用户展示默认创作计划并确认：创作类型为四类（客户痛点：咨询、销售沟通、售后和搜索问题中的困难与误区；案例成果与客户收益：业务改善、实施过程、适用条件和经过脱敏的结果；行业内幕与专业判断：行业规则、采购误区、成本结构、常见风险和趋势变化；产品与解决方案优势：适用场景、解决路径、能力差异、实施过程和限制）。默认计划：每日一篇、长文为先，依据长文生成其他形式和平台的发文内容。请用户确认数量、频度、类型配比是否调整。
B. 依据定位卡与企业资料，用选题公式（目标客户＋具体场景＋真实问题＋专业判断/解决方法＋客户收益）生成不少于 12 条候选选题，写入 04_archive/内容选题库.csv（状态=候选），每条标注创作类型、选题公式拆解、目标受众、参考素材ID（对应素材清单的 MAT 编号，无匹配则写"待补充"）、适用渠道、风险提示。
C. 与用户共创确认后，按月创建台账排期：在 04_archive/内容经营台账.csv 中为下月每一天排一行（默认每日一篇），轮换分配四类创作类型，从选题库中推荐当日选题（状态=待确认），主渠道默认公众号/官网长文，衍生渠道默认小红书图文（可调整）。
D. 将被排期选用的选题在选题库中状态更新为「已入台账」。

【输出】
- 更新 04_archive/内容选题库.csv 与 04_archive/内容经营台账.csv；
- 计划确认与排期摘要写入 03_output/步骤2_创作计划与排期_YYYYMMDD.md，结构：处理摘要、已确认的创作计划参数、选题清单（含类型分布统计）、月度排期概览、待确认事项、人工检查、下一步输入。

【人工检查事项】
- 每条选题是否套用了选题公式五要素；
- 选题类型配比是否与用户确认的一致；
- 选题是否有事实依据（企业资料/FAQ/素材库），禁止臆测。

【异常规则】
- 用户未确认前不写入台账排期；
- 素材不匹配的选题在参考素材ID列写"待补充"；
- 缺失信息写"未找到/待确认"；冲突保留证据提示人工；禁止臆测。

【通过标准】
- 选题库与台账字段符合数据文件规范；
- 台账排期覆盖完整月份且无日期缺口/重复；
- 用户已明确确认创作计划参数。

第三步

业务目标：基于台账的任务安排，分小步完成当日「创作—审核—发布—回写」工作流。以下 3.1–3.7 按顺序执行，每小步均有人工确认点。

3.1 确定当日创作选题

plain text
你是企业内容编辑。请执行「案例4 · 第三步 3.1：确定当日创作选题」。工作目录为案例根目录。

【输入】
1. 04_archive/内容经营台账.csv（当日所在日期的行）；
2. 04_archive/内容选题库.csv；
3. 01_input/02_经营定位/自媒体经营内容定位卡.md。

【任务】
读取台账中今日日期对应的任务行，向用户报告：推荐选题、创作类型、选题公式拆解、主渠道与衍生渠道。如当日无排期，从选题库（状态=候选）中按类型轮换推荐一条并说明理由。请用户确认选题（可直接采纳、更换或修改）。

【输出】
用户确认后：将台账当日行的状态更新为「已确认」（若更换选题则同步更新推荐选题列），并输出确认结果摘要（对话内呈现即可，含选题、类型、渠道）。

【人工检查事项】
选题是否与定位卡的内容支柱一致；更换选题是否仍符合四类创作类型与选题公式。

【异常规则】
台账缺失写"未找到/待确认"；当日排期与选题库冲突时保留证据提示人工；禁止臆测。

【通过标准】
用户明确确认选题，台账状态已更新为「已确认」。

3.2 搜集并整理素材

plain text
你是企业内容研究员。请执行「案例4 · 第三步 3.2：搜集并整理素材」。工作目录为案例根目录。

【输入】
1. 已确认的当日选题（3.1 的确认结果）；
2. 01_input/03_素材库/（素材清单.md 及图片/公司新闻/客户案例子目录）；
3. 01_input/01_企业基本资料/（口径与事实基准）。

【任务】
围绕选题完成素材搜集与整理：
A. 检索本地素材库：按素材清单的 MAT 编号与选题关键词匹配相关素材，读取其内容；
B. 公网补充检索：如本地素材不足，使用联网搜索检索与选题相关的公开行业资料（行业规则、技术标准、趋势报道等）；
C. 将素材整理为「素材卡片」，每张包含：素材ID（本地 MAT 编号或 WEB-序号）、来源（本地路径或网页 URL）、核心内容摘要、与选题的关联点、核验状态（已核验事实 / 教学模拟证据 / 待确认）、可用性判断（可直接引用 / 需脱敏 / 仅作背景参考）。

【输出】
保存至 03_output/步骤3-2_素材整理_选题简写_YYYYMMDD.md（选题简写为选题标题前 10 字以内拼音或汉字），结构：处理摘要、素材卡片清单、事实与证据、待确认事项、人工检查、下一步输入。

【人工检查事项】
- 公网素材是否记录了来源 URL 与检索日期；
- 涉及量化数据是否标注核验状态，未经核验不得写入对外内容；
- 素材内容是否与企业资料口径冲突。

【异常规则】
本地与公网均无相关素材时写"未找到/待确认"，并提示用户改为其他选题或人工补充素材；素材之间冲突保留证据提示人工；禁止臆测。

【通过标准】
每个素材卡片字段完整且来源可追溯；用户确认素材可用后进入 3.3。

3.3 生成文章结构

plain text
你是企业内容主编。请执行「案例4 · 第三步 3.3：生成文章结构」。工作目录为案例根目录。

【输入】
1. 已确认选题（3.1）；
2. 素材整理结果（3.2 的 03_output/步骤3-2_素材整理_*.md）；
3. 01_input/02_经营定位/自媒体经营内容定位卡.md；
4. 01_input/01_企业基本资料/企业B_品牌与内容规范.md。

【任务】
基于选题与素材生成长文文章结构，包含：标题（主标题 + 备选）、开篇钩子说明、章节大纲（每章标题 + 每章要点 + 拟引用的素材ID）、结尾行动引导（合规的 CTA，如"欢迎交流产线诊断话题"，不含报价/承诺）、预估篇幅。结构须体现选题公式五要素的展开逻辑。输出后请用户确认或修改结构。

【输出】
保存至 03_output/步骤3-3_文章结构_选题简写_YYYYMMDD.md。

【异常规则】
素材不足以支撑某章节时，在该章节标注"素材缺口：待确认"，不得虚构填充；冲突保留证据提示人工；禁止臆测。

【通过标准】
用户明确确认结构后进入 3.4。

3.4 生成初稿

plain text
你是企业内容撰稿人。请执行「案例4 · 第三步 3.4：生成初稿」。工作目录为案例根目录。

【输入】
1. 已确认的文章结构（3.3 输出）；
2. 素材整理结果（3.2 输出）；
3. 01_input/01_企业基本资料/企业B_品牌与内容规范.md（语气、禁用表达、案例脱敏要求）；
4. 01_input/01_企业基本资料/企业B_常见问题FAQ与内容口径.md（口径来源）。

【任务】
依据已确认结构撰写长文初稿：语气专业克制、说明适用条件；事实与素材引用须与素材卡片一致并保留可追溯性；涉及价格、交期、认证、服务能力、效果量化一律写"待人工确认"；案例使用遵循"客户脱敏、结果定性、授权先行"。初稿末尾附「事实清单」：逐条列出文中事实及其来源（素材ID 或"AI 分析"标注）。

【输出】
保存至 03_output/步骤3-4_长文初稿_选题简写_YYYYMMDD.md，交用户修改。收集用户修改意见后产出修订稿（保存为 步骤3-4_长文修订稿_选题简写_YYYYMMDD.md）。

【人工检查事项】
初稿是否使用禁用表达清单中的任何表述；事实清单是否完整；案例是否脱敏。

【异常规则】
用户修改意见与品牌规范冲突时，提示冲突并给出合规替代表述，不直接执行；缺失信息写"未找到/待确认"；禁止臆测。

【通过标准】
修订稿经用户确认后进入 3.5。

3.5 审核校验修订稿

plain text
你是企业内容合规审核员。请执行「案例4 · 第三步 3.5：审核校验修订稿」。工作目录为案例根目录。

【输入】
1. 长文修订稿（3.4 输出）；
2. 01_input/01_企业基本资料/企业B_品牌与内容规范.md（第七节内容审核流程 + 第六节禁用表达清单）；
3. 03_output/步骤3-2_素材整理_*.md（核验素材依据）。

【任务】

   e) 风险：本周风险清单（按高/中/低），已化解与新增分别列出。
   f) 下周行动：从台账「下次跟进日期 + 下一步动作」汇总下周 3–5 件最重要的事，标注优先级与责任人。
3. 生成后先在对话中展示周报全文与要点摘要，经我确认后再写入 08_报告与复盘/周报_{YYYYMMDD}.md 并执行推送。

- 周报统计口径需先声明（自然周/滚动 7 天），本周指 {本周起始}～{本周结束}。

步骤 5｜个人案例复盘（对谈式还原 + 苏格拉底式追问）

plain text
你是资深销售教练（复盘搭档）。请协助我对 {客户名称} 的销售案例做一次深度复盘。
案例目标与结果：{例如：报价中推进 / 成功成交 / 丢单 / 长期卡在某一阶段}。

一、先还原过程（先读后问）
1. 阅读该客户在 07_客户跟进/{对应序号}_{客户简称} 子文件夹下的全部资料（基本情况、聊天记录、会议纪要、拜访记录、档案、跟进日志、报价与说明、复盘记录若有），以及 04_archive/01_客户跟进表/ 中该客户的全部台账行与跟进记录明细。
2. 输出「过程还原」：按时间线列出每个销售跟进步骤（首次触达→需求确认→方案/报价→…）与关键动作，标出信息来源（文件/台账/用户补充）。
3. 列出我在资料中看到的「事实缺口」与「判断缺口」——先不要给结论，把缺口整理成问题清单问我（例如：当时为什么选择这个切入点？这个时间点发生了什么？对方的哪句话让你改变策略？）。

二、以对谈方式补充事实（一问一答）
1. 针对缺口清单逐条提问，每次只问 1–3 个问题，等我回答后再继续，不一次性抛完全部问题。
2. 围绕每个销售跟进步骤与工作方向（需求把握、客户关系、竞品应对、报价策略、决策链、推进节奏、内部协同）确认关键事实：当时做了什么、客户怎么反应、依据是什么。
3. 我回答的内容，请复述确认后记为「销售本人确认事实」，与资料事实区分开。

三、苏格拉底式追问（引导归因，不给现成答案）
1. 针对结果成败的关键节点，用提问引导我自己归因，例如：
   - 成功点：当时是什么让你决定这么做？如果换一种做法，你觉得结果会有不同吗？
   - 失败点：如果回到那个节点，你会改变什么？当时的顾虑是什么，这个顾虑后来被证明重要吗？
   - 卡点：这个客户卡在这里，是因为对方没决策，还是我们的价值没被关键人看见？依据是什么？
2. 原则：不直接下结论、不给「标准答案」；每轮追问控制在 2–4 个问题内；若我回答含糊，追问「你当时依据什么信息判断」。
3. 追问结束后，把对话中浮现的有效动作与无效动作整理出来，与我逐条确认。

四、产出两份文件（均先生成初稿，确认后落盘）
1. 个案总结（留档客户文件夹，命名沿用既有复盘版本规则 {客户简称}销售案例复盘_v{版本}_{YYYYMMDD}.md，存入该客户子文件夹；如该客户已有效复盘示例，新版本号递增）：
   - 案例基本信息与结果、过程时间线、关键决策点；
   - 有效动作 ✅ / 无效动作 ❌（各附「为什么有效/无效」及本人确认依据）；
   - 成败归因（区分资料事实、本人确认事实、推测）；
   - 若适用二次激活/继续推进建议；
   - 待人工补充确认的事项清单。
2. 脱敏知识文档（沉淀到 08_报告与复盘/，命名：{客户行业/类型}_销售经验与打法_{YYYYMMDD}.md）：
   - 脱敏要求：不出现客户真实可识别信息（名称改行业/规模特征描述，如「某中型饮料企业」）、不出现当事人姓名、不出现竞品实名；
   - 内容：①案例成败得失总结（一页以内，可对外分享版）②过程中值得学习的方法与经验卡片（每条含场景/做法/话术/适用条件）③对类似客户类似问题的有效开发方法（含分阶段 SOP 与预警信号）；
   - 结尾附「本卡片适用于什么特征的客户」与「不适合照搬的场景」，防止误用。

五、边界
- 复盘结论必须能回溯到资料或对话确认，禁止脑补动机；
- 对销售人员个人的评价性表述只进个案总结，不进可分享知识文档；
- 涉及敏感信息（客户名称、报价、个人）默认不进知识文档，如确需保留请先征得我同意。

演示讲解要点：与「把文件丢给 AI 自动生成复盘」相比，本步骤的差异在对谈还原 + 苏格拉底追问——AI 不替销售归因，而是用提问逼出「当时依据什么判断」。归因来自销售本人，复盘才真正改变后续行为。知识文档 = 把个案经验脱敏后变成团队可复用的资产。

# 步骤3｜两周数据对比与市场机会周报生成

## 业务目标
读取过去两周的竞品监测数据，完成去重与变化对比，按规则生成竞争信号、潜在机会、风险和建议验证动作，输出市场机会周报。

## 输入
- `03_output/<竞品名称>/` 下近两周（含上周）的日期命名档案；若某竞品无历史档案，使用 `01_input/竞品上周监测快照_教学模拟.csv` 作为对比基线（该基线为教学模拟数据，仅用于演示对比逻辑）

作为企业A 的竞争情报分析助理：
1. **去重**：合并近两周全部记录，同一事件多来源重复的只保留一条（注明佐证来源）。
2. **变化对比**：逐家竞品与上周基线对比，识别并归类四类变化：①新品与技术发布；②价格与渠道动作；③区域扩张动作；④重点项目/招投标进展。无变化的明确写"无显著变化"。
3. **生成竞争信号**（至少 3 条）：每条信号注明触发它的证据（事实）、信号等级（高/中/低）、对企业A 的潜在影响。
4. **生成潜在机会与风险**：结合企业A 华东节能空压系统与维保业务，从变化中提炼机会与风险；机会必须可执行（有目标客户群/动作方向），风险必须有应对建议。
5. **提炼一条重点机会**：从全部机会中选出最值得当周投入验证的一条，说明选择理由与建议的验证动作。
6. **建议验证动作**：为每条信号/机会给出低成本的验证方式（如：访问某官网页面核实、联系某区域同事确认、检索特定招投标平台）。

- 周报头部（监测周期、竞品范围、生成日期、数据边界声明）
- 本周摘要（3—5 句话）
- 变化对比表（5 家竞品 × 4 类变化，标注"新增/持续/无变化"）
- 三条竞争信号（证据 + 等级 + 影响）
- 潜在机会与风险清单（含应对建议）
- 一条重点机会（理由 + 验证动作）
- 验证任务清单（可勾选）
- 证据附录（全部来源链接，标注"事实/推论"属性）
- 页面视觉风格参照 `workbench-ui-template/设计说明.md` 的设计令牌（浅米绿画布、白色纸面卡片、衬线标题），单文件内联 CSS 实现，可直接浏览器打开。

## 人工审核与收尾（人工确认后才执行）
周报生成后暂停，等待人工审核：
1. 人工审核信号、机会与风险判断是否成立、重点机会选择是否恰当；
2. 审核通过后：按企业指定渠道推送周报（如企业微信/邮件）；将周报与证据档案归档至 `04_archive/YYYY-WW/`；按验证任务清单创建跟踪任务。
3. 审核不通过：记录修改意见，修订后重新提交审核。

## 异常规则
数据不足以支撑判断时明确写"证据不足，建议验证"，不得强行下结论；教学模拟基线数据须在报告中明确标注"教学模拟"；所有推论标注置信度；禁止编造来源链接。

5. 结果保存为 03_output/02_客户分群与二次销售机会分析.md。

人工检查：分群规则和"二次销售机会"须经我确认后，才能作为后续方案的输入。

步骤3｜为每类客户生成激活方案与触达文案

plain text
基于已确认的 03_output/02_客户分群与二次销售机会分析.md，为每一类客户生成一套激活方案和触达文案：

1. 激活方案包含：活动主题、目标人群（家数与特征）、活动时间、核心价值主张、主推产品、钩子产品（免费诊断/快检等）、执行节奏（首触→跟进→转化）。

3. 对"存在应收账款"的客户，文案设计必须体现"先对账清收、再谈复购"的顺序，不得直接推销。
4. 参考公司背景资料：01_input/ 下的企业A_公司介绍.md、企业A_产品与服务.md、企业A_案例与资质.md、企业A_FAQ与禁用表达.md；话术不得使用禁用表达，不得出现绝对化承诺。
5. 结果保存为 03_output/03_分群激活方案与触达文案.md，并在文末列出通用规则：排除规则（投诉客户不触达）、人工审核要求、分批执行原则（每群首批不超过5家）、回写要求。

plain text
